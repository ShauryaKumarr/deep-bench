# Deep Bench

A daily football quiz. Seven prompts a day, 25 seconds each:

- *Played for Barcelona and Lazio*
- *Played for PSG, from Brazil*
- *A goalkeeper who played for Chelsea*
- *A player from Türkiye who played in La Liga*

Type any player who fits. Wrong guesses cost nothing, so keep going until the clock runs out; your first correct answer locks in. Every correct answer scores, but obscurity pays: the best-known valid answer is worth 10 points and the least known 100, with everything in between ranked by fame. Points win promotion up the English football pyramid, from Sunday league (0) through County league (110), the Northern Premier League (180), National League North (240), National League (300), League Two (360), League One (430) and the Championship (500) to the Premier League (580+). A perfect day is 700.

Leaving the page while the clock is running counts that round as a miss.

## Modes and sharing

- **Today** (`/`): the daily team sheet. Only these count towards streaks and stats.
- **Archive** (`/?archive`, then `/?d=YYYY-MM-DD`): every past team sheet, playable any time. Archive games are flagged `late` in storage and stay out of streaks and stats.
- **Friendly** (`/?friendly`, which becomes `/?f=<code>`): unlimited practice. Seven random prompts built in the browser from `players.json` (nationality, or nationality and position, with the same 6–250 answer and two-well-known rules as the daily), so they never give away a daily prompt. The same code always gives the same seven, so a friendly link can be shared. Friendlies are never saved.
- **Challenges**: every shared result is a challenge link, `/r/<level>?d=<date>&c=<round scores>` (or `?f=<code>&c=…` for a friendly). Whoever opens it plays the same seven prompts and gets a head to head at full time. `c` is two base-36 digits a round (`00` for a miss).
- **Link previews**: `/r/<level>` is a tiny page per pyramid level, generated by `vite.config.ts`, whose Open Graph and Twitter tags show the level the sharer reached (`public/og/<level>.png`). It forwards straight to the game with the query string intact. Preview URLs must be absolute, so they use `https://www.deepbenchgame.com`; set `SITE_URL` at build time to point them somewhere else.
- **Install**: `manifest.webmanifest` and the icons make it installable to a phone's home screen.

The preview cards and icons are drawn with the game's own grounds and screenshotted with headless Chrome or Edge (set `CHROME_PATH` if it isn't found):

```sh
npm run images     # writes public/og/*.png and the app icons
```

Analytics: besides page views, the game sends `kickoff`, `share`, `challenge_open` and `live_join` events through Vercel Web Analytics (custom events need a Vercel plan that includes them).

## Answer stats and live rooms (Supabase)

There are no logins: like Krillion, nobody signs up to play. Each browser gets a random device id, used only so it counts once per round.

- **Answer stats**: when a daily round ends, the browser records which player it named (or none) through the `record_pick` function, and the reveal shows "12% of 1,234 players named him", the most-named answer, and each valid answer's share. The results add each pick's share, and the share text gets "Rarest pick: named by 2% of players" (no names, so no spoilers). Only the current team sheet is recorded; archive days show the stats without adding to them.
- **Live rooms** (`/?live`, which becomes `/?room=<code>`; linked from Friendly): mates play the same seven friendly prompts at the same moment, with a live scoreboard after every round, then a final table and a rematch. It runs entirely on Supabase Realtime presence, with no tables or server code. The longest-serving player in the room is the host, whose page runs the clock (closing a round when everyone has answered or 25 seconds are up, and moving on after the reveal); if the host leaves, the next player takes over. A reload rejoins as the same player.

Setup, once:

1. Create a Supabase project (free tier is fine).
2. In its SQL Editor, run `supabase/schema.sql`.
3. Put the project URL and its publishable (or anon) key in `src/config.ts`, or set `VITE_SUPABASE_URL` and `VITE_SUPABASE_KEY` at build time. Both are public by design: the key can only call the two functions the schema grants and join Realtime rooms.

Until they're set, answer stats stay hidden and the live links don't appear. For local testing without a backend, add `&local` to a room URL in `npm run dev`: the room then runs over BroadcastChannel between tabs of one browser.

## Development

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check and build to dist/
```

The game is a static Vite + TypeScript site with no framework. Progress, streaks and stats live in `localStorage`.

All the pixel art is drawn in code on low-resolution canvases (`src/pixel/`), with no image files:

- **Grounds** (`ground.ts`): one ground per pyramid level, from a wet park with a dog up to a floodlit double-tier bowl. The page background shows the ground for the level you've reached, and its scoreboard shows your points.
- **Replays** (`cutscene.ts`): after each round a short goal plays, matched to the emoji grid. 🟩 is a tap-in, 🟧 a curler, 🟥 an overhead-kick worldie with fireworks, and ⬛ a shot off the bar. Winning promotion adds a climb: the camera rises through the sky to the next ground, floating on its island of turf. Click or press any key to skip; they're skipped entirely with reduced motion.
- **Full time** (`fulltime.ts`): after round seven, the referee blows up, your total counts in, and the division you finished in gets a send-off to match: polite applause in Sunday and County league, fireworks and a lap of honour from League Two up. It can be rewatched from the results screen.
- **Sound** (`src/sound.ts`): whistle, kick, net, crowd, groans, fireworks and 8-bit jingles, all synthesised with the Web Audio API (no audio files). Off by default; the speaker button in the corner turns it on and the choice is remembered.

## Data

`public/data/` is generated by `scripts/build_data.py` (Python 3 with pandas):

```sh
python3 scripts/build_data.py                      # 1,460 days from 2026-11-17 (to 2030-11-15)
python3 scripts/build_data.py --days 2190          # extend further; earlier days stay the same
```

The script shallow-clones both source repositories into `.cache/` (skipping their Git LFS files) and writes:

- `players.json`: every player, ordered from most to least famous, with nationality, position group and first/last season for disambiguation.
- `days/YYYY-MM-DD.json`: seven prompts per day, each with its valid answers ordered by fame.

Days up to today are never rewritten, because people may already have played them (`--keep-through YYYY-MM-DD` moves that line; `--keep-through none` rebuilds everything). Later days are seeded per date, so re-running reproduces them. Keep `--start` at 2026-11-17. Re-cloning the sources (deleting `.cache/`) can reorder players and break published days, so only do that for a full rebuild.

Honours come from a separate script, because they need the network:

```sh
python3 scripts/fetch_honours.py   # writes scripts/honours.json; re-run after a tournament
```

How it works:

- **Clubs.** A player played for a club if they appear in that club's transfer records (the `club` column), in or out, loans included. Club name variants are merged ("Parma FC", "AC Parma" and "Parma Calcio 1913" are all Parma) and shortened for display.
- **Fame** = 0.55 × log-scaled peak value + 0.45 × min(caps, 120) / 120. Peak value is the highest market value or transfer fee on record, with pre-2019 money scaled by 2^((2019 − year) / 5.5). Caps are senior international appearances; the source mixes youth sides in without naming them, so each nation's senior side is taken to be the team its players were capped for most in total.
- **Honours** (`scripts/honours.json`): World Cup, Euros, Copa América and Africa Cup of Nations winners are the winning nation's squad on each tournament's Wikipedia squads page. Champions League finals use the line-ups on each final's page, counting only players who played (starters, and substitutes who came on), which is why prompts say "played in a Champions League final win". Ballon d'Or winners come from Wikidata. Players are matched by their Transfermarkt ID on Wikidata, not by name.
- **Prompts** come in five families, and each day mixes them: two classic (clubs, nationalities, positions, leagues), at least one honours, one transfer, and one international or career prompt. For example:
  - Honours: *Won the World Cup and played in Serie A*, *A goalkeeper who played in a Champions League final win*, *Won the Ballon d'Or and the World Cup*
  - Transfers: *Moved for a fee of €100m or more*, *Joined Juventus on a free transfer*, *Moved directly between Barcelona and Real Madrid*, *Went on loan from Chelsea to an Eredivisie club*
  - International: *Won 100 or more caps and played in La Liga*, *Won exactly one international cap and played for Arsenal*
  - Career: *Played in four of Europe's big five leagues*, *Played for 5 or more different Serie A clubs*, *Played in the Premier League and the Saudi Pro League*

  Every prompt needs 6 to 250 valid answers and at least two well-known ones (in the 1,500 most famous players), uses only the 60 most famous clubs, and never repeats within 150 days.

## Deployment

Deployed on Vercel (`vercel.json`): build command `npm run build`, output directory `dist`. The generated data is committed, so deploys don't need Python.
